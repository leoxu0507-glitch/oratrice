# Offline doctor / self-check

The launcher exposes a static self-check:

```powershell
python scripts/launch_oratrice.py doctor
python scripts/launch_oratrice.py doctor --profile config/profiles/live.yaml --json
```

`doctor` is safe to run on a workstation that has no model files or running
services.  It parses the selected profile with temporary, in-memory
placeholders for missing `${ENV_NAME}` references, validates the declarative
launcher plan, checks configured files/directories, resolves canonical model
and provider aliases, and asks Python whether the declared dependency modules
are discoverable.  It does not construct `Application`, start or inspect a
process, open a socket, make an HTTP request, invoke a browser, or load model
weights.

The statuses have deliberately small semantics:

- `PASS` means the static check is satisfied.
- `WARN` means the profile is structurally valid but the host is not fully
  provisioned (for example, a model binary is not downloaded).  A generated
  launcher secret that is absent from the current environment is also a
  warning.
- `FAIL` means the profile cannot be parsed, a launcher reference/alias is
  invalid, a configured path has the wrong type, a runtime dependency module
  is unavailable, or a required environment variable has no value and cannot
  be generated by the launcher.

The command exits `0` for `PASS`/`WARN` and `1` for `FAIL`.  Human output is a
line per check followed by a `SUMMARY` line.  `--json` emits one JSON object
with `mode: "offline"`, `offline: true`, `checks`, `summary`, `status`, and
`exit_code`; each check has `name`, `check`, `status`, and `message` fields.
Environment variable names may be listed to identify a missing requirement,
but values are never printed or included in JSON.

`--probe` is accepted as an explicit future extension point.  In this release
it only adds a `WARN` saying that probing is disabled; no network or port
probe is performed.
