# Oratrice v0.2.0

Oratrice v0.2 is an accepted local-first text-assistant core for the recorded
Windows deployment. It combines bounded multi-turn Web chat, portable setup,
and verified local-model lifecycle behavior behind provider-neutral contracts.
Stellamurus is the first author and maintainer; OpenAI Codex is the second
author and AI engineering collaborator.

## Delivered

- Typed configuration/registries, replaceable providers, decision-only Gemma
  routing, LiteLLM integration, Core facade, safe errors, and health surfaces.
- Generated local-only profiles, separate Core/Gateway environments, strict
  offline diagnostics, native Windows launcher supervision, and owned cleanup.
- Bounded page-local conversation, context/body limits, reset, draft recovery,
  actual busy feedback, refresh handling, duplicate protection, and keyboard send.
- Explicit RAM prompt-cache budgets, automatic GPU fitting in generated
  profiles, typed startup diagnostics, and read-only acceptance evidence tools.

## Requirements and migration

The tested host has 16 GB RAM and an RTX 4060 Laptop GPU with 8 GB VRAM. Runtime
llama.cpp b9843 (`86b94708f`) served GPT-OSS MXFP4 and Gemma-3n-E4B Q5_K_M. Both
used context 2048, one slot, 16 threads, and `--cache-ram 0`; GPT GPU layers
were `auto`, with Gemma on CPU. This is recorded-host evidence, not a capacity
or performance guarantee for arbitrary machines.

Supply Python, compatible llama.cpp/DLLs, and model weights separately. Follow
the README to install the isolated environments and generate configuration.
Check runtime `--help` for `--gpu-layers auto` and `--cache-ram` support.
Existing profiles are not overwritten. Explicit numeric GPU counts remain
available, and `--prompt-cache-mib N` opts into a finite per-model RAM cache.

The release ZIP contains tracked source and the launcher in its required
relative layout. It includes no model weights, credentials, virtual
environments, generated local configs, or raw logs. Verify its SHA-256 using
`SHA256SUMS.txt`; `RELEASE-MANIFEST.json` identifies the exact source tree,
release commit, CI run, and accepted workload. The existing v0.1.0 is preserved.

## Known limits and deferred work

History is page-local: at most 12 prior messages and 1536 UTF-8 byte/framing
budget units, with replies capped at 256 tokens and a 65536-byte body limit.
Refresh or New conversation resets it. There is no persisted history,
automatic summary, streaming, voice, Memory, Tools, or Agent behavior.

This release covers sequential short text use for 30 minutes on the recorded
host. Continuous uptime, long contexts, high concurrency, other terminal
hosts, Qwen-VL, and real cloud inference require separate acceptance. Default
chat needs no cloud key and never implicitly falls back to a cloud provider.
