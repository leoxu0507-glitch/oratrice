# Oratrice v0.2 candidate

**Status: BLOCKED for stable release (2026-11-03).** The latest real validation
stopped at the recorded three-attempt cap for resource headroom before full
Core readiness. No stable v0.2 tag or release is created from this candidate.

## Scope

The default deployment is a local GPT-OSS text assistant with a decision-only
Gemma router, LiteLLM Gateway, Core API, and bundled Web UI. The Core remains
provider-neutral. Cloud inference requires deliberate configuration and keys;
Qwen-VL and cloud paths remain optional and deferred.

- M9 adds lifecycle recovery, Windows child-process supervision, and one
  shared chat/route admission slot per API instance.
- M10 adds generated local configuration, separate Core/Gateway environments,
  strict offline diagnostics, and portable Windows CI.
- M11 adds bounded recent conversation, complete role-preserving history,
  request/context limits, reset, draft recovery, busy/error feedback, and
  keyboard operation. History remains page-local and resets on refresh.
- M12 adds lighter readiness probing, explicit RAM prompt-cache budgets,
  typed startup diagnostics, reproducible acceptance records, native Windows
  listener-table observation, and automatic GPU fitting in generated profiles.

## Latest repairs and migration

Both model runtimes explicitly use `--cache-ram 0` by default. An explicit
`--prompt-cache-mib N` permits a finite per-model opt-in budget. Generated GPT
GPU layers now default to `auto`; explicit non-negative layer counts remain
supported. Check the installed llama.cpp `--help` for both features (validated
against b9843 / `86b94708f`). Existing operator profiles are not overwritten.
Generate a new profile or migrate a deliberate copy before using these defaults.

A forced GPU layer count of 999 prevented runtime memory fitting in the
recorded failed window. Auto fitting reduced VRAM pressure, but host RAM still
fell below the predeclared 512 MiB availability floor when both models loaded.
The controller stopped the run; this was a resource-guard stop, not a proven
OOM crash. Auto fitting does not reserve RAM for the router or establish that
the complete deployment fits arbitrary hardware.

## Remaining limits

- The tested host has 16 GB RAM and an RTX 4060 Laptop GPU with 8 GB VRAM.
  Resource evidence applies to that host/window and selected models/settings.
  It does not prove that an upgrade is the only remedy or that smaller
  deployments are unusable; neither alternative was validated here.
- Python, llama.cpp and its runtime DLLs, and model weights are user-supplied.
  The source archive is not a self-contained model installer.
- Recent history permits at most 12 prior messages, 1536 UTF-8 byte/framing
  budget units, and 256 reply tokens. The body limit is 65536 bytes. There is
  no persistent history, automatic summary, or streaming.
- Earlier real browser/context/reset/busy-recovery checks remain historical
  evidence; the latest generated auto-fit profile did not reach a new full
  UI/Core acceptance run.
- Browser closure ends the browser wait. The launcher owns model lifetime;
  normal close/restart behavior still needs real-model acceptance.
- Qwen-VL and real cloud inference have separate acceptance gates and do not
  block the declared default local-text scope.

Keep the candidate PR as a draft and preserve `v0.1.0`. Stable v0.2 requires a
changed resource window, reproducible readiness/restart/close and sustained-use
evidence, defect review, exact-source CI, and matching release checksums.
